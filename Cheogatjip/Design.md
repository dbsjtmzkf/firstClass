# 처갓집양념치킨 웹사이트 리뉴얼 — Design System

> 기준 화면: `Cheogatjip/index.html` + `Cheogatjip/css/main.css`  
> 목적: 메인페이지의 실제 구현을 기준으로 서브페이지의 시각적 일관성을 유지한다. 이 문서는 관찰된 스타일과 현재 코드의 규칙을 기록하며, 디자인에 없는 토큰이나 수치를 임의로 추가하지 않는다.

## 1. Project Overview

- 프로젝트는 처갓집양념치킨 브랜드의 웹사이트 메인페이지 리뉴얼이다.
- 구현은 HTML, CSS, JavaScript 기반이며 Swiper를 사용한 메인 비주얼, 추천 메뉴, 브랜드 웹진 영상, 매장 안내, 앱 홍보, 푸터로 구성된다.
- 메인페이지의 디자인은 기준으로 유지한다. 서브페이지는 기존 컴포넌트와 시각 규칙을 재사용하고, 새로운 레이아웃이 필요할 때도 브랜드 톤을 벗어나지 않도록 한다.
- 페이지 이동 링크는 프로젝트 내부 페이지 또는 페이지 내 앵커로 연결한다. 기존 브랜드 공식 사이트 등 외부 사이트로 연결하는 링크를 새로 만들지 않는다. 외부 링크가 필요한 경우 별도 요청 전까지 내부 화면으로 대체하거나 비활성 상태를 명시한다.

## 2. Brand Identity

### 시각적 특성
- **브랜드 인상:** 따뜻하고 친근한 치킨 브랜드 이미지를 바탕으로, 정돈된 기업형 웹사이트 구조를 사용한다.
- **주요 브랜드 컬러:** 레드 계열을 강조색으로 사용하고, 흰색·밝은 회색·짙은 회색/브라운 계열로 콘텐츠와 정보를 정리한다.
- **이미지 중심:** 메뉴 사진과 프로모션 배너가 주요 시각 요소다. 사진은 지정된 비율을 유지하고 `object-fit: cover` 또는 `contain`을 목적에 맞게 사용한다.
- **브랜드 로고:** 헤더 중앙에 배치하며, 원본 이미지 비율을 유지한다. 로고에 임의의 효과나 색상 변경을 적용하지 않는다.

## 3. Design Principles

1. **브랜드 일관성:** 레드 강조색, Pretendard 계열 글꼴, 밝은 배경, 정돈된 카드와 섹션 구성을 유지한다.
2. **콘텐츠 우선:** 메뉴·영상·매장 등 콘텐츠를 명확한 섹션 제목과 설명으로 구분한다.
3. **재사용:** 헤더, 섹션 제목, 카드, pill 버튼, 푸터를 우선 재사용한다.
4. **이미지 비율 유지:** 메뉴 썸네일은 정사각형, 영상은 16:9, 배너는 원본 비율을 유지한다.
5. **반응형 우선:** 고정 폭 화면을 만들지 않고 `min()`, `clamp()`, 퍼센트 폭과 미디어쿼리를 이용해 축소한다.
6. **접근성:** 링크와 버튼의 역할을 구분하고, 아이콘 버튼에는 접근 가능한 이름을 제공한다.
7. **내부 연결:** 새 링크는 구현된 프로젝트 페이지 또는 내부 앵커를 사용하며, 외부 브랜드 사이트로 임의 연결하지 않는다.

## 4. Color System

현재 `main.css`에는 전역 `:root` 색상 변수 시스템이 확인되지 않는다. 아래 색상은 실제 CSS에서 사용된 값이며, 디자인에 없는 토큰명이나 컬러는 추가하지 않는다. 새 서브페이지에서 공통 토큰화가 필요하면 기존 값만 변수로 정리하고, 메인페이지의 렌더링 결과를 바꾸지 않도록 한다.

### 사용 규칙
- 브랜드 강조나 선택 상태에는 해당 컴포넌트에서 사용 중인 레드 값을 사용한다. 임의의 새로운 레드를 추가하지 않는다.
- 큰 콘텐츠 영역은 흰색 또는 현재 지정된 연회색 배경으로 구분한다.
- 본문은 어두운 색, 보조 설명은 회색으로 계층을 만든다.
- 어두운 패널에서는 흰색 텍스트와 현재 사용된 밝은 회색 보조 텍스트를 사용한다.
- 색상은 요소의 의미에 맞춰 사용하고, 장식 목적으로 여러 색을 추가하지 않는다.

## 5. Typography

### Font family
- 메인페이지에서 Pretendard Variable을 사용한다.
- HTML은 `../font/css/pretendardvariable.css`를 연결한다.
- 헤더 GNB와 푸터에서 `"Pretendard Variable", Pretendard, sans-serif`를 명시한다.
- 다른 폰트를 새로 도입하지 않는다. 실제 폰트 파일/경로가 확인되지 않으면 임의로 경로를 추가하지 않는다.

### 실제 사용 크기 및 굵기
| 대상 | 크기 | 굵기 | 행간 / 특징 |
|---|---:|---:|---|
| GNB 링크 | 22px (모바일 10px) | 700 | `line-height: 1`, 한 줄 유지 |
| 헤더 유틸리티 링크 | 12px (모바일 9px) | 500 | `line-height: 1.2` |
| 섹션 eyebrow | 13px (메뉴/매장 변형 12px) | 800 | `letter-spacing: .12em` 또는 섹션별 .2em |
| 섹션 제목 | `clamp(28px, 3vw, 44px)`; 메뉴/매장 `clamp(30px, 3vw, 40px)` | 800 | 기본 1.25, 메뉴 제목 1.2 |
| 섹션 설명 | 18px (모바일 축소 규칙 적용) | 기본 | `line-height: 1.6` |
| 메뉴 카드 제목 | 17px (모바일 14px) | 800 | `line-height: 1.4` |
| 메뉴 설명 | 13px | 기본 | `line-height: 1.5` |
| 메뉴 가격 | 14px (모바일 12px) | 800 | 단일 행 |
| 웹진 제목 | `clamp(22px, 2.2vw, 30px)` | 800 | `line-height: 1.35` |
| 웹진 설명 | 15px | 기본 | `line-height: 1.8` |
| 푸터 정보 | 14px (모바일 12px) | 기본 | `line-height: 1.55` |
| 버튼/탭 | 13–14px | 600–700 | 버튼 높이와 정렬을 우선 |

### 적용 방식
- 서브페이지 제목은 섹션 제목의 크기·굵기 체계를 기준으로 한다.
- 본문은 가독성을 위해 15–18px 범위를 우선하되, 메인페이지의 해당 컴포넌트 규칙을 따라야 한다.
- 작은 메타 정보는 eyebrow나 footer의 실제 크기를 참고한다.
- 모바일에서는 기존 미디어쿼리의 축소 규칙을 적용한다. 임의로 전체 글꼴을 확대/축소하지 않는다.

## 6. Layout & Spacing

### 컨테이너 / 정렬
| 영역 | 실제 규칙 | 사용 상황 |
|---|---|---|
| 헤더 내부 | `width: min(100% - 64px, 1200px)` | 데스크톱 헤더 콘텐츠 정렬 |
| GNB | `width: min(100%, 1120px)`, gap 36px | 헤더 주요 메뉴 |
| 일반 섹션 | `width: 100%`, padding 88px 24px | 메인 콘텐츠 섹션 |
| 섹션 제목 | `max-width: 1100px`, 가운데 정렬 | 섹션 소개 문구 |
| 메뉴 카드 그리드 | `width: min(100%, 1210px)`, 4열, gap 16px | 데스크톱 메뉴 카드 |
| 웹진 카드 | `width: min(100%, 1320px)`, 2열 비율 .7fr/1.3fr | 설명 + 영상 배치 |
| 매장 feature | `width: min(100%, 1280px)`, 2열 | 매장 이미지 + 검색/프로모션 |
| 앱 배너 | `width: min(100%, 1648px)` | 배너 원본 비율 유지 |
| 푸터 | `width: min(100% - 40px, 1400px)` | 푸터 정보 및 링크 |

### 간격 / 그리드
- 섹션은 기본적으로 상하 88px, 좌우 24px padding을 사용한다. 모바일에서는 48px 16px로 축소한다.
- 섹션 제목과 본문 사이에는 기본 36px 정도의 간격이 있으며, 모바일은 24px로 줄인다.
- 메뉴 카드 그리드는 데스크톱 4열, 900px 이하 2열로 전환한다.
- 웹진과 매장 콘텐츠는 넓은 화면에서 2열, 767px 이하에서 1열로 바뀐다.
- 카드 내부 여백과 gap은 컴포넌트별 CSS를 우선한다. 새 화면에서 별도 spacing scale을 만들지 않는다.
- 레이아웃은 Grid/Flex를 목적에 맞게 사용한다: 카드 목록은 Grid, 헤더/버튼/링크 묶음은 Flex, 콘텐츠+미디어는 Grid.

## 7. Components

### Header / GNB
- 흰색 배경의 헤더이며 로고는 중앙, 상단 유틸리티 링크는 우측, GNB는 로고 아래에 배치한다.
- 데스크톱 GNB는 22px 굵은 텍스트와 넉넉한 간격을 사용한다.
- GNB hover는 브랜드 레드로 전환한다.
- 메가 메뉴는 7열 구조, 연회색 배경, 컬럼 구분선, 아래로 펼쳐지는 전환을 사용한다.
- 모바일에서는 로고와 GNB 높이를 줄이고, GNB를 가로 스크롤 가능하게 한다.
- 서브페이지 헤더를 만들 때 동일한 로고/유틸리티/GNB 구조를 재사용하고, 메뉴 링크는 프로젝트 내부 경로로 연결한다.

### Section heading
- eyebrow(영문 소제목) → 한글 제목 → 설명 순서.
- 중앙 정렬이며 eyebrow는 레드, 제목은 어두운 색, 설명은 회색/기본 텍스트로 구성한다.
- 새 서브페이지의 주요 영역에도 이 순서를 유지한다.

### Menu card
- 이미지 영역은 1:1 비율, 둥근 하단 모서리, 이미지 `object-fit: cover`.
- 이미지 좌상단에 BEST/NEW 배지를 배치한다.
- 카드 정보는 제목 → 짧은 설명 → 가격 순서.
- hover 시 이미지는 `scale(1.035)`로 확대한다.
- 카드 자체는 현재 메인에서 정적 article이다. 링크 동작이 필요하면 실제 상세 화면을 구현한 뒤 카드 전체를 내부 링크로 감싼다.

### Pill tabs / buttons
- 메뉴 탭은 pill 형태, 얇은 회색 테두리, 흰 배경, 어두운 텍스트.
- 활성/hover 상태는 레드 배경과 흰 텍스트.
- 주요 이동 링크는 pill outline 스타일이며 hover 시 레드 배경/흰 텍스트로 전환한다.
- 클릭 동작이 있는 UI는 `button`, 페이지 이동은 `a`를 사용한다.

### Webzine feature
- 설명과 영상의 2열 카드, 흰색 패널, 가는 경계선, 둥근 모서리.
- 영상은 16:9 비율로 표시한다.
- 더보기는 outline pill 링크이며 hover 시 레드로 바뀐다.
- 슬라이더에는 원형 이전/다음 버튼과 pill 형태의 페이지네이션을 사용한다.

### Store finder
- 이미지와 콘텐츠 패널의 2열 레이아웃.
- 검색 패널은 짙은 브라운/차콜 배경, 흰 제목, 밝은 설명, pill 검색 입력으로 구성한다.
- 매장 찾기 CTA는 브라운 배경이며 hover 시 더 짙은 브라운으로 바뀐다.
- 검색/매장 이동 기능은 실제 구현된 내부 화면 또는 기능으로 연결한다.

### App banner
- 배너 이미지는 원본 비율을 유지한다.
- 앱 배지 버튼은 검은색 pill, 아이콘과 두 줄 텍스트를 사용한다.
- hover 시 배경이 밝아지고 약간 위로 이동한다.
- 프로젝트 내 앱 소개/다운로드 화면이 없는 경우 외부 앱스토어 링크를 임의로 추가하지 않는다.

### Footer
- 상단 퀵링크 바는 레드 배경, 흰 링크, 세로 구분선을 사용한다.
- 본문은 흰 배경, 회사 정보는 회색 텍스트, 브랜드 마크와 SNS 링크는 우측 정렬(모바일은 세로 흐름).
- 푸터 링크도 새 서브페이지에서는 내부 구현 페이지/앵커로 연결한다. 브랜드 공식 사이트로 직접 연결하지 않는다.

## 8. Interaction

- **Link hover:** GNB는 `#d71920`, utility/webzine/menu/footer는 해당 컴포넌트에 정의된 레드 또는 underline을 사용한다.
- **Button/tab hover:** 배경/테두리/텍스트 색을 함께 바꾸어 상태를 분명히 한다.
- **Image hover:** 메뉴 카드 이미지에 0.35s ease 확대 효과.
- **Transition:** 일반 색상 전환은 약 0.18–0.2s ease, 메가 메뉴는 opacity/transform/clip-path를 이용한 약 0.3–0.42s 전개.
- **Active:** 메뉴 탭과 웹진 pagination은 `is-active` 클래스로 표시한다. 탭에는 `aria-selected`, 페이지네이션에는 `aria-current` 상태를 함께 갱신한다.
- **Focus:** 메가 메뉴 링크는 `:focus-visible` 상태에서 레드와 underline을 사용한다. 새 인터랙티브 요소에도 키보드 focus가 보이도록 한다.
- **Disabled/loading:** 현재 메인페이지에 공통 disabled/loading 디자인 토큰은 정의되어 있지 않다. 임의의 시각 규칙을 공통화하지 말고 실제 상태가 필요한 경우에만 별도 명시한다.

## 9. Responsive Rules

| Breakpoint | 현재 구현된 기준 |
|---|---|
| `max-width: 900px` | 메뉴 카드 4열 → 2열, 푸터 간격/링크 크기 축소 |
| `max-width: 767px` | 헤더 축소 및 GNB 가로 스크롤, 섹션 padding 48px 16px, 웹진/매장 1열, 푸터 세로 배치, 앱 배지 크기 축소 |
| `max-width: 600px` | 푸터 링크 줄바꿈, 회사 정보와 SNS 링크 간격/폰트 축소 |
| `max-width: 480px` | 메뉴 탭·카드 간격 및 카드 텍스트/배지 크기 추가 축소 |

- 모바일에서 고정된 390px 너비를 지정하지 않는다. 부모 폭에 맞추고 최대 너비를 제한한다.
- 이미지와 영상은 `width: 100%` 및 비율 기반 높이를 사용한다.
- 모바일 메뉴는 화면 밖으로 잘리지 않도록 가로 스크롤을 허용한다.
- 새 페이지는 위 breakpoint를 우선 사용하며, 다른 breakpoint가 필요하면 해당 화면의 실제 콘텐츠 문제를 근거로 추가한다.

## 10. Do & Don't

### Do
- 메인페이지의 CSS와 HTML을 먼저 확인하고 기존 class/패턴을 재사용한다.
- Pretendard Variable, 브랜드 레드, 밝은 배경, 정돈된 섹션 구조를 유지한다.
- 기존 이미지 파일과 실제 경로를 확인한 후 사용한다.
- 메뉴/영상/매장 등의 이미지 비율을 유지한다.
- 페이지 이동은 구현된 프로젝트 내부 페이지 또는 앵커로 연결한다.
- 링크와 버튼의 역할을 구분하고 hover/focus/active 상태를 제공한다.
- 메인페이지를 변경하지 않고 서브페이지에 필요한 스타일만 추가한다.

### Don't
- 메인페이지의 기존 디자인이나 레이아웃을 임의로 변경하지 않는다.
- 디자인에 없는 컬러, 폰트, 간격, breakpoint를 임의로 발명하지 않는다.
- 브랜드 공식 사이트나 다른 외부 사이트로 링크를 연결하지 않는다.
- 존재하지 않는 서브페이지/이미지/폰트 경로를 가정하지 않는다.
- 모든 요소를 카드화하거나 과도한 그림자/그라데이션/장식을 추가하지 않는다.
- 모바일 화면을 고정 폭으로 만들지 않는다.
- 페이지 이동에 `#`만 남겨 실제 동작이 있는 것처럼 보이게 하지 않는다.
- 메인페이지에 이미 구현된 스타일을 별도 정의로 덮어쓰지 않는다.
